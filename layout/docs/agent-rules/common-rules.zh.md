# Go-Spring 通用规约

本文件适用于 Go-Spring 框架仓库,以及所有基于 Go-Spring 的项目。

## 设计原则

保持简单。不要为边界情况添加防御性代码，除非由外部输入、真实 bug 或明确需求驱动。

不要仅仅为了改名而重新导出或包装类型和函数。封装必须带来契约、约束或语义转换；否则直接导入原包。

配置的默认值放在 `value` 标签里，不要写在消费配置的代码里。依赖注入体系下，标签负责给未配置的字段填默认值；代码里直接构造的结构体则必须显式给出同样的默认值。测试同样遵循标签默认值，不要因为零值能编译就传空。

扩展性是判断而非条件反射：在应用代码中，越过判断线（对外契约 / 第二实现已可预见 / 用户需替换默认行为）才留扩展点。详见编码风格文档「可扩展性与扩展点」一节。

除非用户明确要求，否则遵循现有代码模式和项目风格。

## 编码风格

参见 [coding-style.md](../coding-style/coding-style.zh.md)，涵盖命名、格式与组织、错误处理、测试、并发、Go 习惯等风格取向。

## 代码卫生

- 代码必须通过 `modernize` 和 `go fix`，不得有任何告警。

## 脚本

- 需要脚本时，优先使用 bash，其次 python。
