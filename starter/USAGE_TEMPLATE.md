# Starter 使用文档模板（维护者用）

每个 starter 在自己的目录维护 `USAGE.md` / `USAGE_CN.md`，按本模板撰写。使用文档不是 README
的加长版：README 回答"这是什么、值不值得用"，使用文档回答"我怎么把它跑起来、配全、运维好"。
写作必须锚定一个**编译通过且冒烟验证过的 example**——example 起不来，文档不许写"能跑"。

## 文档范围（硬边界）

starter 是对成熟组件的封装，go-spring 的增量价值在**可观测、服务治理、配置统一、装配接线**
四个方面。使用文档只写这四方面的增量；**组件自身的功能与语义引用官方文档**（链接 + 版本），
不复述、不翻译、不重新举例。具体：

- 配置参考只解释**我们绑定时的语义**（前缀、默认值、与官方默认的差异、key 间的耦合），
  字段对组件的含义一句话带过 + 指向官方文档对应章节
- quickstart 只演示"接进 go-spring"的最小路径（依赖、配置、注入、启动），组件用法示例
  （怎么发消息、怎么写查询）不写，给官方链接
- 注入与 API 一节完整保留——bean 面是我们的
- 可观测与运维一节完整保留且重点写——这是增量核心
- 判定口径：删掉官方文档能补回来的内容后，剩下的一定都是 go-spring 的增量；反过来，
  若某节删完什么都不剩，说明这个 starter 没有增量价值，记入设计嫌疑清单

## 结构

```markdown
# <starter> 使用说明

## 1. 快速开始（Quickstart）
最小可运行配置 + 最小用户代码。硬性要求：
- 从 `go get` 到日志出现"启动成功"的完整步骤，一步不省
- 配置文件直接复制自 example（不存在的 example 先补）
- 列出前置外部依赖（注册中心/数据库/镜像等）及其启动命令

## 2. 全量配置参考（Configuration Reference）
按实例前缀分组的所有配置 key：| key | 类型 | 默认值 | 必填 | 说明 |
硬性要求：
- 必须与代码中 value tag 一一对应，写完用脚本核对（见下）
- 互相耦合的 key（改 A 必须改 B）显式标注 ⚠ 并解释为什么

## 3. 注入与 API（Beans & API）
- 提供哪些 bean：类型、名字、注入方式（autowire 示例代码）
- 程序化 API：方法签名 + 何时调用
- 扩展点：用户可实现/可替换的接口

## 4. 可观测与运维（Operations）
- 日志 tag（如有，链接 logger.<tag> 配置）
- 健康检查 / 指标 / trace 的开启方式
- 优雅退出行为；故障排查入口（常见报错 → 原因 → 处置）

## 5. 设计体检表（Design Health，写作时填写）
| 指标 | 数值 |
|------|------|
| 配置 key 总数 | |
| 其中必填 | |
| quickstart 前置外部依赖数 | |
| 文档中"注意/坑"条数 | |
- 设计嫌疑清单：写作过程中发现的复杂度来源，每条一行
  （现象 → 怀疑的设计问题 → 建议动作），攒够一批交设计裁决
```

## 写作规则

1. **不解释内部实现**。出现"因为内部……所以你需要"即记入设计嫌疑清单。
2. **每个代码块可复制**。import 路径、模块名完整。
3. **双语同源**：USAGE_CN.md 与 USAGE.md 内容一致，标题本地化、术语保留英文（同 README 惯例）。
4. **配置核对**：文档写完执行
   `grep -rhoE 'value:"[^"]+"' <starter> --include='*.go' | sort -u`
   与文档表格比对，两边都不许有多余项。
5. **体检表不美化**。数字大的先记嫌疑，不要为了好看拆分文档。

## 裁决判据（趋势参考，非硬门槛）

- 必填 key > 5：装配默认值可能不足
- quickstart 依赖 > 2 个外部系统：考虑提供 embedded/内存模式
- "注意/坑" > 5 条：接口设计在与用户预期作对
- 单 key 说明写不满一行、且无人配置它：候选删除

## 参考手册级标准（2026-08-27 用户拍板：全维度深度）

每份 USAGE 必须达到六节深度（样板：starter/starter-echo 的 USAGE.md/USAGE_CN.md）：

1. **完整工程示例**：多文件工程（go.mod/main/业务文件/完整注释配置），组合 actuator/otel/
   governance 等生态件的真实配置，附验证命令——不是单文件片段
2. **装配与时序**：bean 生命周期时间线（import→绑定→装配→Run→就绪→停机）、链/钩子的精确
   顺序**与设计理由**（引源码注释）、一次请求/一次调用的逐层走读
3. **逐 key 行为参考**：每个 key 的类型/默认/行为/联动/配错后果（表格五列），枚举值展开，
   耦合与死 key 显式 ⚠
4. **验证与故障演练**：每个能力给可执行的验证命令（curl/grep/metrics 读取）；故障注入演练
   步骤（含热切换）；观测字段解读（指标名+属性、日志字段、span 命名）
5. **排障表**：症状→原因→处置，≥6 行
6. 设计体检表 + 嫌疑清单

写作来源纪律：行为声明必须引源码核对（函数/注释），演练命令必须与 example 冒烟同构；
组件语义仍链接官方文档。
